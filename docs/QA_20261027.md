## Fixes made

- Added one shared, persistent feedback component for errors, warnings, information and success. Action feedback appears in the document flow beside the initiating controls. It scrolls into view, remains readable, and does not cover controls. Dialog errors stay inside the active dialog. Camera errors are scoped to the camera panel.
- Added semantic alert/status roles and consistent severity colors. Legacy IDE CSS no longer overrides the shared error palette. Technical GPU errors retain expandable details with a concise capacity explanation.
- GPU startup in the IDE now polls for its final result, instead of leaving a stale progress message after startup fails. Business GPU request errors remain visible. Tests confirm that visiting setup does not start a VM and a failed start does not silently retry.
- Unified the Business App with the IDE's dark surfaces, text, focus outlines and feedback styling. Kept its larger typography and touch-oriented layout. Removed the external font dependency. Improved floor-plan label/grid contrast and ensured Business App buttons are at least 44 × 44 CSS pixels.
- Applied the dark style to the shared login page. Fixed a rejected IDE access code failing to show its explanation. The explanation is an in-flow alert below the submit control.
- Verified NVIDIA marks remain centered with labels; removed the duplicated visible “NVIDIA” beside the Isaac setup wordmark while preserving the accessible name.
- Isolated the full IDE browser suite from actual saved projects. It now owns temporary example projects, robot definitions and runtime state. Removed cleanup that could target real source data. Made remote worker contract fixtures explicit across host operating systems.
- Fixed a rejected second server launch deleting the active server's launch record. A direct duplicate-launch check confirms the existing authority record is preserved.
- Stabilized visual/drag test synchronization around scene loading and transitions; teardown explicitly permits cancelled mock polling requests. Functional motion/feedback assertions remain enforced.

## GCP and native validation limits

The existing `nvdiavm / asia-south1-c / robot-ide-isaac` VM was available briefly during this QA session and subsequently stopped after inactivity. Later starts were rejected **three times** with `ZONE_RESOURCE_POOL_EXHAUSTED_WITH_DETAILS` for the L4/G2 allocation. No replacement VM, additional persistent disk, zone migration or reservation was created.

Consequently, this session could not finish either **Electron → live GCP Isaac** or **both web applications hosted on GCP → live Isaac**. The Linux production deployment check used real server-side planning and the built-in simulator, with contract tests covering the Isaac transport and handoff. It does not replace native GPU acceptance.

Earlier native acceptance evidence is retained in `artifacts/gcp-setup-20261027/native-validation.json` and `project-preview-validation.json`: two-robot movement and confirmed Stop, object addition/removal, mesh transfer and a copied four-robot project scene. Those results predate this QA pass and are **not counted as a fresh cloud retest**.

Final provider state is recorded in `artifacts/qa-20261027/gcp-vm-state.json`: **TERMINATED**, automatic restart disabled, maximum run duration **7200 seconds**, termination action **STOP**. The existing idle policy remains 10 minutes; no persistent shutdown safeguard was relaxed for these checks.

Other unvalidated external cases:

- Native Windows execution and Windows/Linux Electron packaging; no native Windows host was available.
- A physical phone camera or actual speech-recognition service. Chromium used a fake camera and controlled recognition/permission events. Real HTTPS deployment and device/browser permissions still determine availability on phones.
- New NuRec GPU reconstruction/training from a real room capture. Capture/upload, service contracts, USD room references/checksums and inventory were tested; no NuRec trainer was run.
- Real manufacturer hardware, a native ROS 2 deployment, and arbitrary custom SDK/provider integrations. Simulated transport, mapping, limits, arming, ownership, feedback, cancellation and Stop contracts were exercised without contacting hardware.
